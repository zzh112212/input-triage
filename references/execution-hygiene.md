# 执行卫生协议（Execution Hygiene）

> 实时处置的时序细则、重锚定协议、任务列表卫生、防污染话术、与 .planning/ 的配合。

## 处置时序：立即识别 ≠ 立即执行

"实时"指的是**识别与登记**实时，不是每类插话都当场执行：

| 类别 | 识别 | 登记 | 执行 |
|---|---|---|---|
| ADD | 立即 | 立即写入任务列表 | 到计划位置再执行 |
| CORRECT | 立即 | 立即裁决入台账 | 立即转向 |
| ASK | 立即 | 立即写入搁置区 | 收尾补答 |
| NOISE | 立即 | 写搁置区（或极简登记） | 永不执行 |

ADD 写入任务列表是廉价操作（一次 todo 更新），当场做完；它的**执行**等任务列表排到那一步。这样用户的"突然想到"不会丢，也不会打断当前步骤——这正是"实时吸收、延后执行"的价值。

## 重锚定协议（打断恢复）

**触发**：任何插话处理完毕后、任何被打断的输出恢复时。

**动作**（四步，全程几秒钟）：

1. 重读任务列表 / `.planning/task_plan.md` 的 Next Step；
2. 确认：当前在第几步？状态是什么？
3. 用半句话向用户锚定位置："继续第 3 步：……"
4. 从锚点继续执行。

**禁止**：凭"感觉刚才在做什么"继续——打断后的记忆最不可靠。**文件与列表是唯一可信锚点**（这就是 context-continuity 把状态落盘的原因，两个技能在此天然衔接）。

## 任务列表卫生

1. **唯一权威状态**：任务列表 > 对话记忆。任何"我记得用户要过 X"都要能在列表里找到出处，找不到就当它没说过。
2. **写入权限**：ADD/CORRECT 可写；ASK/NOISE 永远不进。
3. **物理隔离**：搁置区独立成文件（templates/parking-lot.md）或独立区块，与任务列表零混排。
4. **吸收必须可追溯**：每条 ADD/CORRECT 在台账留痕：原文摘要 → 分类 → 列表变更。

## 防污染话术（借鉴 fresh-context）

任务态输出（任务描述、成果文件、交接简报、总结报告）里**禁止**出现：

```
❌ "如我们之前聊到的天气那样……"     （引用噪声原文）
❌ "既然你问了 X，那我顺便……"       （为噪声展开行动）
❌ "根据刚才的讨论，任务还要……"      （把闲聊混入任务需求）
```

只写任务事实：

```
✅ "第 3 步完成：配置文件已写入，测试通过。"
✅ "已按用户修正将数据格式从 JSON 改为 YAML。"
```

**原理**：插话删不掉，但每被引用一次就多"存在"一分。引用是污染的放大器；不引用，它就只是过眼云烟。

## 与 .planning/ 的配合（context-continuity 在场时）

| 本技能的对象 | 落点 |
|---|---|
| 任务列表 | `.planning/task_plan.md`（Phases / Next Step） |
| 台账（吸收记录） | `.planning/progress.md` 追加，或独立 task-log.md |
| 搁置区 | `.planning/parking-lot.md` |
| 交接 | `handoff.md` 引用台账 + 未清空搁置项写入开放问题 |

无 `.planning/` 的短任务：对话内 todo 即任务列表，搁置区用一条消息内的表格维护，规则不变。

## 上下文卫生的三个"不为"

对 NOISE：**不为它调用工具、不把它写进文件、不在回复正文展开**。做满这三个"不为"，污染就被压到了物理下限。
